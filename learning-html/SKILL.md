# 生成学习资料 HTML（Learning HTML）

用户要学一个新领域/新技术时，生成一套**可读性高、分章节、图文并茂、循序渐进**的 HTML 学习资料。本技能的核心价值有五点，做任何决策时都先回到它们：

1. **HTML 阅读体验**：排版、配色、代码高亮、图表、导航都做到「打开就能舒服地读」。
2. **渐进式连续性**：章节按认知阶梯编号（01、02…），每章承上启下，学完一章自然想学下一章。
3. **图文并茂**：每章至少 1-2 张图，优先 HTML/CSS 原生泳道图（不依赖任何库、离线可用），辅以 Mermaid 各类图。
4. **内容厚度**：宁可多写解释、类比、例子，不要干巴巴列要点——用户要的是「宽度和广度兼顾」。
5. **固化模板、风格统一**：排版、配色、字体、代码高亮、图表样式、深浅色切换等**所有视觉原则都已在本技能的 assets/ 中提前定死**。每次生成的站点长得几乎一样，用户读得越多越熟悉排版——因此生成内容时**只填内容、绝不改动样式或结构**。

## 阶段 0：加载本技能资源

动手前先读取这些打包资源，生成时严格复用：

| 资源 | 用途 |
|---|---|
| `assets/chapter-template.html` | 章节页骨架模板：**每个章节文件都基于它**，保留全部结构块，只替换内容 |
| `assets/index-template.html` | 目录页骨架模板：index.html 基于它 |
| `assets/style.css` | 共享样式，**原样复制**到输出目录的 `assets/`，不要改动（除非修 bug） |
| `assets/app.js` | 共享脚本：章节导航自动生成、Mermaid/高亮 CDN 加载与离线降级、学习进度 localStorage，**原样复制** |
| `assets/swimlane-example.html` | 泳道图两种变体的完整示例，画泳道图前先看它 |
| `references/diagram-guide.md` | 图表选型规则与全部写法（泳道图、Mermaid 各类型 + 语法铁律），画图时对照 |
| `references/content-guide.md` | 章节规划模板、每章内容构成、写作风格与篇幅规范，规划大纲时对照 |
| `scripts/validate-mermaid.mjs` | **Mermaid 语法校验脚本**（阶段 4 必跑），用 Mermaid 官方解析器逐个 parse 所有图表 |

模板是「骨架 + 每种组件的完整示例」二合一：即每个结构块旁都有已填好的样例，照着样例替换即可，不要自创结构。

## 阶段 1：需求澄清（信息不足时才问）

先盘点用户已经给了什么，**已给的信息绝不重复问**。缺失的关键项用**一轮、最多 5 个问题**问清，每个问题都给选项式默认值，方便用户秒回：

1. **目标领域/技术**（必填）：学什么？
2. **现有基础**：完全零基础 / 有邻近领域经验 / 有相关基础 / 该领域已资深
3. **学习目标**：了解概览 / 能上手使用 / 深入原理并能实战 / 应试或认证
4. **篇幅偏好**：精简（每章 2000-3000 字）/ 标准（每章 4000-8000 字，默认）/ 深度（每章 8000+ 字）
5. **内容偏好**：要代码示例吗？要自测题吗？有没有特别想覆盖的子主题？

规则：

- 用户回答「你看着办 / 都行 / 随便」时，启用默认：标准篇幅、含代码与练习、基础按领域常识合理假设（说「想学」就默认从零基础起步）。
- 若领域明显是常规技术学习场景（用户说「我想学 XX」且没给更多信息），**不要死板追问全部 5 项**——按默认配置直接进入阶段 2，最多补问 1-2 个真正影响大纲的问题（如基础、是否要代码）。
- 问题要具体、给默认值，例如：「你的编程基础是？A. 完全零基础 B. 会一点编程 C. 有 X 领域经验 D. 资深」。
- 澄清完成后，把「领域 + 基础 + 目标 + 篇幅 + 内容偏好」写成一两句话的生成配置，在开始生成前给用户看一眼确认（用户没异议就继续）。

## 阶段 2：大纲规划（循序渐进曲线）

对照 `references/content-guide.md` 的规划模板，按 **8-12 章**设计，遵循认知阶梯（可微调但顺序不变）：

| 位置 | 主题 | 目的 |
|---|---|---|
| 01 | 领域概览与价值 | 全景图、为什么学、能做什么、术语扫盲，建立整体认知 |
| 02 | 环境搭建 + 第一个例子 | 让用户 5 分钟内「跑起来」，建立信心 |
| 03-05 | 核心概念由浅入深 | 每章聚焦 1-2 个大概念，配图配例，讲透为止 |
| 06-08 | 进阶原理与最佳实践 | 底层机制、常见模式、性能/安全/工程化最佳实践 |
| 09-10 | 综合实战 | 一个贯穿性案例，从零逐步搭起来 |
| 11 | 常见问题与排错 | 高频坑 + 排查方法 + 调试手段 |
| 12 | 总结与进阶路线 | 知识地图、自测、后续学习路径与资源 |

按用户基础调整深度：

- **零基础**：01-02 加厚铺垫（背景故事、生活化类比），03-05 放慢节奏。
- **有基础**：压缩 01-02，把省下的篇幅投给 06-08 进阶与 09-10 实战。
- **资深/面向提升**：直接以 03 起步，06-08 为核心，多讲权衡、对比、底层原理。

每章必须定义元信息：**标题、3-6 条可勾选的学习目标、前置章节、与前后章的衔接点**。章节标题要具体（如「04 Docker 镜像与容器：核心抽象」），不要只有「第四章」。

## 阶段 3：生成 HTML（核心）

### 输出目录

默认在当前工作目录创建 `<topic>-learning/` 子目录（topic 用英文短横线 slug，如 `docker-learning/`）；用户指定了路径就用指定路径。若目录已存在且是旧的，先确认是否覆盖。

### 文件结构（自包含站点，file:// 直接打开即可用）

```
<topic>-learning/
├── index.html            # 目录页（封面、学习路线、章节卡片、进度总览、学习建议）
├── 01-overview.html      # 每章一个文件
├── 02-setup.html
├── ...                   # 共 8-12 个章节文件
└── assets/
    ├── style.css         # 从技能 assets/ 原样复制
    └── app.js            # 从技能 assets/ 原样复制
```

### 硬性规则

- **章节文件名** = 两位数字 + 英文 slug：`01-overview.html`、`02-setup.html`…；中文标题写在 HTML 里。编号连续无重复。
- **每个章节页** = 基于 `chapter-template.html` 的完整页面，保留全部结构块：学习目标（可勾选）、正文小节、图示、代码示例、术语卡片、自测题、本章小结、延伸阅读。结构块只增不减。
- **index.html** = 基于 `index-template.html`：封面信息、学习路线图、章节卡片（编号+标题+目标摘要+链接）、进度总览、学习建议。必须内嵌 `window.CHAPTERS` 章节清单（章节模板同样内嵌，两份保持一致），app.js 据此自动生成每章的上/下一章导航与目录页进度条——**不要手写上一章/下一章链接**，交给 app.js。
- **相对路径**：`assets/style.css`、`assets/app.js` 全部相对引用，保证 file:// 打开正常。
- **每章至少 1-2 张图**，图文并茂。
- **深/浅色切换**：每页页头右侧必须有 `<button id="theme-toggle" class="theme-toggle">`（模板已内置，照抄即可），默认浅色，用户点击可自由切换，app.js 会记住选择。**不要**自行改用系统自动跟随、不要去掉这个按钮。
- **固化模板，只改内容不改样式**：`assets/style.css` 与 `assets/app.js` 必须从技能目录**原样复制**，绝不改动（包括配色、字号、间距、高亮主题、图表样式、主题切换逻辑）。排版/高亮/图表/深浅色等视觉原则全部已固化，任何"我觉得这样更好看"的自创样式都会破坏「每次阅读风格一致」的目标——统一由模板保证设计感，模型只负责填高质量内容。

### 图表规范（详见 `references/diagram-guide.md`）

| 场景 | 用什么 |
|---|---|
| 多角色/多系统协作流程（谁做什么、怎么流转） | **HTML/CSS 泳道图**（`class="swimlane"`，首选） |
| 单线流程 / 算法步骤 | Mermaid `flowchart` |
| 交互时序（请求/响应） | Mermaid `sequenceDiagram`（自带泳道感） |
| 状态流转 | Mermaid `stateDiagram-v2` |
| 数据模型 / 表关系 | Mermaid `erDiagram` |
| 时间计划 / 学习路线 | Mermaid `gantt` |
| 占比统计 | Mermaid `pie` |

泳道图要点：泳道 = 参与者行，时间从左到右；步骤卡片 + 箭头；**每个泳道用颜色编码**（`data-lane` 属性）；图上方有标题、下方有 aria-label 和一段文字说明。「图文并茂」= 图 + 解释文字，缺一不可。写法直接复制 `swimlane-example.html` 中的完整示例再填充。

Mermaid 块写法：`<div class="mermaid">flowchart LR ...</div>`，app.js 负责从 CDN 加载渲染，**加载失败自动降级为可读源码文本**（离线也能看到图的内容）。

**Mermaid 语法铁律（写图时必须遵守，否则渲染报错）**：Mermaid 语法错误会导致图渲染失败，这在 HTML 里是致命的，必须从源头避免。核心规则：

- **所有节点标签和子图标题一律加双引号**：`A["前向: pred = model(x)"]`、`B{"是错误吗?"}`、`subgraph A ["形状 (3,1)"]`。凡是标签里含 `(`、`)`、`=`、`/`、`?`、`:`、`<br/>` 或中文标点等，不加引号几乎必报 `Syntax error`。
- **边标签用 `-->|"标签"|` 形式**（有空格或特殊字符时尤其要加引号）：`A -->|"size mismatch"| B`，不要用 `A -- size mismatch --> B` 这种裸写法。
- 其余类型（sequenceDiagram / stateDiagram-v2 / erDiagram / gantt / pie）严格照 `references/diagram-guide.md` 里的可运行示例套用，不要自创语法。

### 代码与内容规范

- 代码块用 `<pre><code class="language-xxx">`；app.js 用 highlight.js 高亮，失败自动降级为纯文本。代码必须有注释和「预期输出/效果」说明。
- 每章 4000-8000 中文字（标准模式；精简 2000-3000；深度 8000+）。全套标准模式 ≥ 4 万字。
- 术语首次出现加粗并进术语卡片；用生活化类比讲抽象概念；例子密度要高。
- 自测题 3-6 题，用 `<details>` 折叠答案（离线可用，无需 JS）。
- 章节衔接：开头一句话回顾上一章，结尾一句话预告下一章。

## 阶段 4：交付自检（生成完必须逐项检查）

1. 文件清单完整：index.html + 8-12 个章节文件 + assets/ 下两个文件都存在。
2. 章节编号连续、无重复、slug 合法。
3. index.html 中的 `window.CHAPTERS` 与实际文件一一对应，链接都能解析。
4. 每章有 `id="chapter-nav"` 容器（app.js 会自动填导航）。
5. 每章至少一张图（`class="swimlane"` 或 `class="mermaid"`），图旁有文字说明。
6. `assets/style.css`、`assets/app.js` 已复制且被每页引用。
7. 内容总量达标（标准模式全套 ≥ 4 万字；精简模式 ≥ 1.6 万字）。
8. HTML 结构合法（标签闭合、无残留模板占位符如 `TODO`、`{{ }}`）。
9. **Mermaid 语法校验（必做，不可跳过）**：用打包好的脚本逐个 parse 每个 `.mermaid` 块，报告任何语法错误并修复：

   ```bash
   node <本技能目录>/scripts/validate-mermaid.mjs <输出目录> --mermaid-root <含 node_modules 的目录>
   ```

   - `--mermaid-root` 填能解析到 mermaid+jsdom 的目录（DSH 环境即你的系统提示里给的 deepseek-harness checkout 路径）。
   - 脚本输出 `✗ <文件>#<序号>` 即语法错误，逐条修复（多半是标签没加引号），重跑到「错误 0 个」为止。
   - 若脚本提示「未找到 mermaid 无法校验」，则改回人工逐块核对 `references/diagram-guide.md` 的语法铁律，尤其检查每个标签是否加了双引号。

发现问题立即修复，不要带着已知问题交付。完成后向用户汇报：**输出目录、章节数、总字数、打开方式（浏览器打开 index.html）**。若用户想要线上访问，提示可以配合 popo 技能部署，但不要主动部署。

## 常见错误（务必避免）

- 只生成一个 HTML 或没有 index.html（用户需要目录导航）。
- 忘记把 `assets/style.css`、`assets/app.js` 复制到输出目录（页面会裸奔/链接 404）。
- 擅自改动 `style.css`/`app.js` 的样式、配色、主题切换逻辑，或删掉页头的主题切换按钮（破坏「固化模板、风格统一」）。
- 章节文件没有编号前缀或编号跳跃。
- 手写上一章/下一章链接（容易写错文件路径；应该交给 app.js 自动生成）。
- 泳道图没有颜色编码、没有文字说明，或把简单流程硬凑成泳道图。
- Mermaid 节点标签/子图标题没加双引号、或边标签用了 `-- 裸文本 -->`（导致 Syntax error，图渲染不出来）——写图前看 `references/diagram-guide.md` 的语法铁律，生成后必跑 `scripts/validate-mermaid.mjs`。
- 内容空洞：只有标题列表没有解释、类比、例子。
- 生僻术语不解释、不进出术语卡片。
- 图与文字脱节（图和正文各说各话）。
- 遗留模板占位符（TODO、{{placeholder}}、示例内容未替换）。
