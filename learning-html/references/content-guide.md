# 内容指南（content-guide）

本文规定：章节大纲怎么规划、每章装什么、怎么写才能「宽度和广度兼顾」。

## 一、渐进式章节规划（8-12 章）

固定认知阶梯，顺序不变、主题可微调：

| 位置 | 主题 | 每章核心任务 |
|---|---|---|
| 01 | 领域概览与价值 | 全景图 + 为什么学 + 能做什么 + 术语扫盲 + 学习路线 |
| 02 | 环境搭建 + 第一个例子 | 5 分钟内「跑起来」，建立信心 |
| 03-05 | 核心概念由浅入深 | 每章聚焦 1-2 个大概念，讲透为止 |
| 06-08 | 进阶原理与最佳实践 | 底层机制、模式、性能/安全/工程化 |
| 09-10 | 综合实战 | 一个贯穿性案例，从零逐步搭建 |
| 11 | 常见问题与排错 | 高频坑 + 排查方法 |
| 12 | 总结与进阶路线 | 知识地图 + 自测 + 后续路径 |

### 按用户基础调整

- **完全零基础**：01-02 加厚（背景故事、生活化类比、为什么需要它），03-05 放慢。
- **有邻近经验**：压缩 01-02（快速过），把篇幅投给 06-08 与 09-10。
- **资深/提升向**：从 03 起步，06-08 是主体（权衡、对比、原理），少讲「是什么」多讲「为什么/怎么选」。

### 章节元信息（每章必写）

- 标题：具体化（「04 Docker 镜像与容器：核心抽象」），不要「第四章」。
- 学习目标：3-6 条，动词开头（能解释/能搭建/能排查…），学完可自检。
- 衔接：开头一句回顾上一章，结尾一句预告下一章。

## 二、每章内容构成（结构块只增不减）

1. 学习目标（可勾选）
2. 正文小节（h2/h3 分层，编号 1.1 / 1.2…）
3. 图示 ≥1-2 张（泳道图优先，Mermaid 补充），每图带编号+说明
4. 代码示例（有注释 + 预期输出）
5. 术语卡片（3-8 个）
6. 自测题（3-6 题，details 折叠答案）
7. 本章小结（3-5 条 bullet，呼应学习目标）
8. 延伸阅读（1-3 条，给名字+一句话理由）
9. 上一章回顾 / 下一章预告

## 三、写作风格（宽度与广度兼顾的关键）

- **篇幅目标**（按用户选择的模式）：
  - 精简：每章 2000-3000 中文字，全套 ≥1.6 万字
  - 标准（默认）：每章 4000-8000 中文字，全套 ≥4 万字
  - 深度：每章 8000+ 中文字
- **宁可多写，不要空洞**：每个概念至少配「一句话定义 + 生活化类比 + 领域内例子 + 代码/图示」四件套里挑 2-3 件。只有标题没有解释的章节 = 不合格。
- **术语管理**：首次出现加粗；生僻术语进术语卡片用大白话解释，不要抄官方文档。
- **例子密度**：每章至少 2-3 个具体例子。抽象概念先用生活化类比（快递/银行/餐厅…），再落到领域例子。
- **广度**：每章涉及的概念要提「它和相邻概念的关系」（对比表、取舍表很有效）。
- **深度**：进阶章要讲「为什么这样设计」「不这样做会怎样」「业界怎么权衡」。
- **语言**：全中文，口语化但准确；代码注释中文；避免机翻腔。

## 四、自测题规范

- 3-6 题/章，难度递进：复述概念 → 解释原理 → 场景应用 → 开放思考。
- 答案必须给出（`<details><summary>题目</summary><div class="a">答案</div></details>`），答案要解释为什么，不只给结论。
- 题面要具体，不要「XX 是什么？」这种一句话题。

## 五、实战章（09-10）规范

- 用一个**贯穿性案例**（如「从零搭建一个 XX 应用」），两章内逐步完成：拆需求 → 设计 → 编码 → 运行 → 验证。
- 每步给出完整可运行的代码 + 预期输出 + 常见报错。
- 章节间强衔接：第 9 章结尾停在「下一步要做 X」，第 10 章开头承接。

## 六、篇幅不够时的取舍顺序（不要牺牲的）

1. 可以砍：延伸阅读数量、次要小节。
2. 可以压：代码注释（但保留）、类比数量。
3. **不可以砍**：学习目标、图示、术语卡片、自测题、小结、章节衔接——这些是「连续性」和「图文并茂」的骨架。
