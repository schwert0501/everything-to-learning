Swimlane Diagram Example (native HTML/CSS)

Variant H: Horizontal Swimlanes (classic)

Lanes = rows (participants), time flows left to right. Best for showing collaboration flows between 2-4 participants; this is the go-to form.

Example: User Login Flow

Stage User Frontend Backend
Initiate login
Enter credentials
Validate form→POST /login
Verify credentials
Return result
Enter the home page
Render success page
Issue token→Return

Login flow: collaboration among three participants across two stages. An empty swimlane cell means that participant does not take part in the current stage.

Variant V: Vertical Swimlanes

Lanes = columns (participants), time flows top to bottom. Best for flows with many steps or longer individual steps.

Example: Order & Payment Flow

Stage Buyer Store system Payment channel
1. Place order
Confirm order
Lock inventory
2. Pay
Choose payment method
Create payment order
Debit the account
3. Complete
Receive confirmation
Update order status
Send callback notification

Order & payment: a vertical swimlane with three participants, time running top to bottom, with stage labels on the left.

How to Extend

  • Add lanes: change --sw-lanes: N and add a matching number of participant columns in sw-head and in every sw-row; when there are more than 5 participants, cycle through the l1-l5 color schemes.
  • Add stages: append a .sw-row.
  • Multiple steps in one cell: put several .sw-step elements inside a single .sw-cell, connected with <span class="sw-arrow">→</span>.
  • Branches: write the steps as two paths, e.g. "A → B (condition) → C / D", and label the condition in words.
  • Change colors: lane colors are determined by data-lane, mapped to --lane-1..5 in style.css.
⚠️ When NOT to use a swimlane diagram

Single-role single-line flows (a Mermaid flowchart fits better), pure state transitions (stateDiagram), and request-response sequences (sequenceDiagram). The value of a swimlane diagram lies in showing the division of labor and the flow among multiple participants.
